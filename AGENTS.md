# forge-vfx Agent Guide

Instructions for coding agents working in `pkg/forge-vfx`, the emit module behind the [VFX Forge](https://devforum.roblox.com/t/3867553) Roblox plugin.

Follow this whether you are changing code here directly or preparing a PR. Code that does not match the style below will be sent back.

**Before writing any Luau, read `.agents/skills/forge-luau-style/`.** It is the canonical rule set: `SKILL.md` for the rules and procedure, `reference.md` for the full evidence and worked corrections. This file is the summary; that directory is the authority. Both describe this package only. The parent plugin repo has its own conventions and its own guide, and nothing here is a rule for it.

`.agents/` is deliberately tool-agnostic. If your assistant discovers skills from its own directory, symlink to it rather than copying, e.g. `mkdir -p .claude/skills && ln -s ../../.agents/skills/forge-luau-style .claude/skills/forge-luau-style`. Tool-specific directories are gitignored, so a copy will drift and nobody will see it.

## Tests

Tests here are for what plays: an effect's timing, a modifier's value at a given time, a codec, a legacy format read. Write one when a bug there would change an effect silently. Do not write one that restates the implementation or would pass before and after the change, and delete a feature's tests with it. While working, run the specs near the change; run `lune run tests/run` once before a release. A flaky test is fixed or deleted, never rerun until it passes.

## Layout

| Path | Contents |
|---|---|
| `src/effects/` | One module per effect, every effect there is; each declares its rows and `emit(ctx, attrs, props)` |
| `src/play/`, `src/mod/lazy.luau` | What an effect plays, apart from what it declares: `src/effects/<name>.luau` keeps the rows, the layout, the rules and every function the plugin reads before an emit, and its `emit` (and `selected`, `init`, `deinit`, `hook` where it has them) hands on to `src/play/<name>.luau`, a unit it declares with `lazy.unit(id, load, start?)`. A unit loads where it is declared, at the top of the module that declares it, as its requires did before; a host that calls `lazy.defer()` before the index is required (the plugin) gets every unit at its first need instead, through the one getter `lazy.unit` answers (or `lazy.need`), and loads them ahead with `lazy.prepare(name?)`. `src/services/runtime.luau` is the dispatch, the pool and the loops as one unit. A play module never requires the module that declares it (a function level cycle stops darklua's bundler): what it shares with it is handed over by `bind` in the load. Deferred, `init` answers the units the place's enabled and preloaded instances need now, the runtime last, for the host to load at its own pace |
| `src/effects/forge_lightning.luau`, `src/mod/lightning/` | The lightning, a built-in written against the module's own `knob`, reader, lifetime and play paths like every other effect (it began as a custom effect on the sdk, and nothing in it requires the sdk now). `init.luau` registers it last and flagged as a custom effect the runtime ships (`registry.register(module, true, true)`, `registry.isBundled`), so it is classified ahead of the built-ins and plays through its rows alone as it did when the sdk assembled it, its id and classifier are taken before any place's module loads, and a host lists it beside the built-ins and adds it from its `template`. `lightning.luau` is the old effect, named "Lightning (legacy)", kept as it is for the games that use it until it ships as a custom effect of its own. The new code may use `const` (lune 0.11 is pinned) |
| `src/mod/` | Plain-table helper namespaces (`tween`, `lerp`, `logger`, `attributes`) |
| `src/mod/curve.luau`, `src/mod/curves.luau` | A value over time. `curve.new(duration, shape)` is a Curve: its `duration` and `at(t)`, the value at `t` from 0 to 1. A shape is a preset name (`linear`, `easeIn`, `easeOut`, `easeInOut`, kept as serialized bytes in `curves.PRESETS`), a serialized editor path (a curve row's value, string or buffer), a chain of `vector`s (x the time, running 0 to 1, and y the value, which may leave 0 to 1 to overshoot, y up; 2 or 3n + 1 points, time running forward, a bad one refused with the reason) or a function of `t`. Shapes are cached by content, at most 256 besides the presets, least recently used out first, so a Curve is a duration and a reference and building one per emit costs nothing; `curve.sample(shape, t)` is the same read with no Curve; `curve.sampler(shape)` is that read with the shape looked up once, as a function of `t`, for a caller sampling one shape every frame. `curves.preset(name)` answers a row's curve value and `curves.default()` the out cubic every effect always eased with |
| `src/mod/tween.luau` | The one tween core. `tween.play(scope, eased, fn, follow?, done?)` plays a Curve on the effect's clock, held by the effect: `fn(alpha, deltaTime, elapsed)` sees its first value at once and one a frame after, the last at the curve's end; it ends there, when `fn` answers `false` or when the clock halts for good, and calls `done` then, never on a clear. `follow` is the depth it follows at, else it computes at depth 0. `tween.wait(scope, eased, fn?, follow?)` plays the same and parks the calling thread until it ends. `tween.drive(scope, track, write, follow?, done?)` writes a row's track: its first value at once, and one a frame while the track is animated, calling `done` as `tween.play` does; `done` is called only for an animated track, since a static one writes once and never calls it |
| `src/mod/shape.luau` | Where a piece starts: `shape.box`, `cylinder`, `sphere` and `disc`, each `(cframe, size, options?)` with `options` of `surface`, `partial`, `normal` and `seed`, answering a CFrame facing out along the normal. With no seed they draw from one generator; a seed draws the same point every time |
| `src/mod/lerp.luau`, `src/mod/color/color.luau` | `lerp.any(a, b, t)` blends two values of one type; a Color3 or a ColorSequence blends in Oklab, and a NumberSequence keeps the engine's 20 keypoints and warns once past them. `color.blend`, `toOklab`, `fromOklab`, `inGamut` and `sequenceAt` sit on the vendored Oklab and sRGB modules |
| `src/mod/lifetime.luau` | Emit and effect records: `hold`, `defer`, `lock`, `run`, `clear`, `await`, `step`, `wait`, `kill`, `join`, `add`, `include`, `spawn`, `awaitJoin`, `speed`. Each emit and each effect carries a `clock` (`src/mod/clock.luau`); `lifetime.speed(scope, row)` makes an authored Speed row the effect's clock, or with a third argument a clock the effect holds below its own (an EmitDuration window's), its track stepped on the clock above so it never scales itself. Effects file resources through `lifetime.hold(scope, x)`, never `table.insert(scope, x)`; a Handle the scheduler returns is filed with the connections, and one with no owner is adopted by the effect. A property or attribute an effect writes but did not make goes through a writer: `lifetime.write(scope, obj, source, name)` once, `lifetime.set(writer, v)` every time it writes, and the writer leaves with the effect (or at `lifetime.leave`); the target's owner is the highest `priority`, a one-shot emit over a ConstantVFX tick, then the newest, and the last to leave puts back what was there. `lifetime.hook` is what `hookProperty` and `hookAttribute` hand game code. `lifetime.step(scope, fn, phase)` is a step held and owned by the effect, at the effect's depth; `lifetime.wait(scope, seconds)` parks whichever thread of the effect calls it on frame time, does not yield for a length of 0, below 0 or not finite, and never resumes once the effect stops; a wait whose effect's clock is halted for good kills the effect (released as cancelled) instead of resuming it, so what follows a delay that never elapsed never runs; `lifetime.kill` is what a throwing step's owner gets; an effect waits for its own pieces and child emits through a join: `lifetime.join(scope)` makes one, `lifetime.add(join)` counts one thing in and answers a count-out that works once, `lifetime.include(join, emit)` counts a child emit until it is done by any means and clears it if the including effect ends first (a throw or a kill), `lifetime.spawn(join, fn, ...)` runs a piece on a thread the effect holds (a throw is logged once and counted out), and `lifetime.awaitJoin(join)` parks until the count is 0, or returns at once when its effect is no longer running. The count is live, so anything counted in while the body waits is waited for; the service's `emitNested`, `emitFromFolder` and `emitOnFinish` take the join as their last argument |
| `src/mod/scheduler.luau` | The one frame loop. Phases `undo wait compute` run at `RenderPriority.First` and `shake screen follow` at `Last + 1` in a running game, all six from one `RenderStepped` connection in the editor; every phase runs by depth, shallowest first (an effect's steps sit at its `fx.depth`). `scheduler.add(phase, run, depth?, owner?, survives?, timeline?)` returns a Handle (`Connected`, `Disconnect`) and steps on `timeline` if given, else on its owner's clock, else on `clock.REAL`; steps run in the order they were added, one added during a pass runs from the next pass of its bucket. A step that throws is dropped and logged once, and its owner, if it has one, is handed to `scheduler.failed`, which `lifetime` sets to kill it; a step with no owner ends alone. `scheduler.adopt(handle, owner)` gives an ownerless step the owner that holds it and moves one on `clock.REAL` onto the owner's clock from its next frame; `lifetime.hold` adopts every step it is handed, so a tween, which its effect always holds, kills its effect when it throws. Only a service step kept for the session passes `survives` (the debris physics step, camera shake's undo and shake steps, the pool's sweep): it stays connected after a throw and warns once. Never pass it for a step an effect or a tween owns. `api.init` starts it and `api.deinit` stops it. Outside it only the passive ConstantVFX loop in `src/services/enabled_effects.luau` keeps a loop of its own, until the plan that replaces it; a passive tick counts its rate on its token emit's clock (`enabled_effects.token()`, under `clock.global`) and does not tick while that clock stands still. An EmitDuration window's ticker is a step its effect holds, at depth 0 on `clock.REAL`, counting the window's clock |
| `src/mod/mods.luau` | Modifier queues. `mods.build` turns a lane map into a Track and returns, second, a function handing the same piece-independent lanes to another piece of the same events (nil when some lane draws or schedules per piece); the reader keeps it per row so one read builds its lanes once for every piece. `mods.track` is the read-and-build behind it, and the only caller left is the mesh's decal, a knob authored on an instance the dispatcher reaches on its own. `legacy_mods` reads the old attribute format and owns every quirk of it (`ALIASES`, `CURVES`, `SPANS`, `DRAWN_RANGES`). A row's stored modifiers are a map from lane name to queue: `start` fires at the emit, `end` at `span - reach(end)`, and every other lane is an event a module declares in `module.events` and fires with `piece:fire(name, elapsed, runFor)`; `runFor`, when the firer knows how long the phase it opens runs, is what an entry on that lane naming no duration runs out instead of the effect time left. `track.reach(lane)` is how long a lane's entries run from its trigger, zero for a lane the row does not hold or one that snaps; never shorten it for a lane that moves nothing, since a phase length (lightning's released bolt) reads it. `track.still(lane, at)` is true when the lane, fired at `at`, leaves the row where it stood then for its whole reach (every entry a chained tween to one literal equal to that value, nothing drawn or waited) and no lane starting after it takes the row (every other lane the row holds has already fired, at or before `at`, and not later in the same frame), and true for a lane the row does not hold; an exit stepper uses it to stop sampling a row, never to change how long the exit runs. A lane's entries play one after another, lanes run together; a stored map replaces only the default lanes it names (an empty named lane silences one, an empty map silences none); `delay` is an entry that waits before what follows; an endpoint `{ t = "feed", ref }` reads what the randomizer with that `id` in its queue drew, and a randomizer an endpoint names is off the clock and sets nothing itself (`modifiers.sources`); an entry naming a `share` and no duration runs that fraction of the effect duration; an entry naming no duration runs for the effect time left from where it starts (none on the `end` lane). An entry naming an `fpsMax` beside a plain `fps` steps at a rate drawn between the two once per roll (`modifiers.rateOf`), at `fps` with no roll; it rides the codec's `extra`, so an older runtime steps at `fps`, and a ramp (`fps` as `{ from, to, curve }`) draws nothing. An entry naming a `durationMax` beside its `duration` draws its length between the two once per roll (`modifiers.lengthOf`), the shortest with no roll; it rides the codec's `extra`, so an older runtime plays the shortest. An entry carrying `outlast` (a number, one per old child) is an old Tween Property child the plugin's store kept, on the first write of the row and only where the place's module plays such entries (its `Capabilities` attribute names `outlast`, or its `Version` is 3.1.0 or later: default.project.json stamps both on every build, and the release refuses a tag its `Version`, wally.toml or package.json disagree with), on an effect whose pieces played it nested: `emitters.outlast` drives it on each piece through the same `drive` an old child played through, on the emit of the piece's children (`effects.emitNested`'s fifth argument names the instance the piece was copied from, whose outlasting entries `emitters.outlasting` works out once per dispatch read of it, never off the instance again), so the piece stays up until it ends and its reset applies as it ends; the applier never drives one (`mods.applied`), and the row's own track plays them only when the map holds nothing else (`mods.played`), as the old read played a row's children only when no quad or map stood before them. An older runtime plays such entries as ordinary ones: cut at the effect's end, and on a row the effect owns without their reset and speed ramp. `mods.build` folds the lanes inside the track; there is no arbitration layer and no second stepper. A sampler compiles its queue once (`modifiers.compile`, placed again by `modifiers.place` when an open-ended lane is told a new time left) and reads it each frame through `modifiers.sample`, which answers exactly what `modifiers.evaluate` answers; `evaluate` stays for a caller with no sampler, such as the plugin's bake. A row of one lane is read straight off that lane, without the fold. Neither path may differ from the fold or from `evaluate` at any elapsed: `tests/track_paths.spec.luau` compares the lanes against the fold copied at 22f78f0 (`tests/fixtures/mods_22f78f0.luau`, which pins 22f78f0's lane rules: re-point or retire it when one changes on purpose) and the sampler against the live `evaluate` |
| `src/mod/knob.luau`, `src/mod/mod.luau` | Row and default-modifier builders an effect module declares its rows with: `knob(x)` chained `min max aliases options label hint curve unit hidden readonly slider mod`; `knob.legacy(row, rule)` decides what a row rests at where nothing usable is stored, for old content, while the default stays what a new instance rests at and what the plugin shows (a module function, so sdk 1's knobs never reach it); a knob's unit is one of `seconds perSecond perSecondSquared studs studsPerSecond studsPerSecondSquared studsCubedPerSecondSquared` (the last a gravity mass, which time scales by the square and size by the cube); `mod.from(a)` / `mod.to(b)` chained `duration curve delay lane`, and `:mod(...)` takes one or more specs, one lane each |
| `src/mod/registry.luau`, `src/mod/reader.luau` | The effect registry (`register unregister problems get list of scan read source alternatives`; `problems(module, except?)` answers every reason a module cannot be registered, and `register` raises them all at once; `scan(root, claimant)` finds every registered effect plus every legacy tween RayValue no module's row already reads, and drops what the root's own module claims, asking no module whose subject classes nothing under the root is (`FindFirstChildWhichIsA(class, true)` once per class a scan needs, no answer kept between scans); a Track is called as `track(current, span)` for a piece's own state and clock, or `track(current, span, piece)` when its event lanes fire on that piece's clock; a Track answers `at(elapsed, own, since)`, `has(lane)`, `reach(lane)` and `still(lane, at)`) and the reader that resolves a module's rows into one frozen `attrs, props` pair per emit |
| `src/mod/retime.luau`, `src/mod/resize.luau`, `src/mod/recolor.luau` | One walk over a classified instance's rows by `unit`, editing what each row answers to: retime scales spans and rates, resize lengths, recolor the color rows. `PROPERTY_UNITS` and `RATIOS` are the two tables they keep for engine properties no row names and for the ratios resize scales as lengths (a mesh's Size curve among them, scaled key by key through `value_curve.multiply` in place of its template) |
| `src/mod/clock.luau` | The clock tree every step and wait advances on: `clock.global` (the global speed and pause, times every Global controller), each emit's clock (its handle) under it or under the effect that started it, a controller's region clocks, and each effect's clock (its authored Speed). A clock's factor is its parent's times its `speed` and every `scale`, 0 while `paused`, worked out once a frame and pinned before any change, so a change reaches it and everything below it from the next frame; `clock.refresh(c)` is the one way an owner's own later steps see its change on the same frame. While no clock is off 1 (`clock.uniform`), the scheduler hands each step the frame's delta untouched. `clock.watch` calls back once a frame with a factor that moved; `clock.speedChanged` and `clock.pausedChanged` are the API's `SpeedChanged` and `PausedChanged` signals (vendored GoodSignal, `pkg/GoodSignal.luau`), and `api.setSpeed`, `pause`, `resume` and their getters only read and write `clock.global`; `clock.wall` is real time only a global pause stops; `clock.REAL` is what a step with no owner advances on. A `halted` clock stays at 0 but hands what hangs from it its parent's factor times its own scales (its `through`), so a nested or on-finish emit of an effect whose Speed rests at 0 still runs out. `clock.setSpeed` and `clock.scale` ignore a NaN or infinite value |
| `src/mod/adapters.luau` | What puts an engine-timed piece under its effect's clock: `particle` (TimeScale up to 1, the emitter's time rows retimed above it; `authoredOf` answers what an in-place emitter held before any emit wrote it), `beam` (TextureSpeed), `sound` (PlaybackSpeed, Pause and Resume), `debris` (the launch impulses it applies itself, scaled before the engine takes them, a VectorForce for gravity, anchored while paused). Each restores what it wrote when its effect ends. `adapters.create` is the seam a spec stands an Instance in through |
| `src/mod/common/` | Pure helpers with no engine access, requirable under lune |
| `src/mod/common/state_list.luau` | A forge mesh's list of states, stored in its `States` attribute: `encode` and `decode` (versioned; `encode` raises on a value it cannot store), `toPlain` and `fromPlain` for the bridge, `seed(rows)` from the rows, `scaled` for a resize, `pose(base, position, rotation)` (radians) and `sampler(list, rest)` for playback. `MAX` is 32 states |
| `src/mod/common/path_curve.luau` | A forge mesh's path, stored in its `Path` attribute: `encode` and `decode` (versioned; `encode` raises on a value it cannot store, `decode` answers nil for one it cannot read), `toPlain` and `fromPlain` for the bridge, `scaled` for a resize, and the placement every consumer shares: `place` (a similarity fit of the drawn curve to a piece's spawn and end, with Bend), `ending`, `at` and `trace`. `MAX` is 64 anchors |
| `src/obj/` | Class modules with metatables (`Bezier`). `Bezier.new(points)` is a 3D path through a chain of `vector`s (an anchor, its outgoing handle, the next anchor's incoming handle, the next anchor; 3n + 1 points, or 2 for a straight segment): `at(t)` over the raw parameter, `tangent(t)`, `atUniform(u)` evenly along it and `length()` in studs. `set(points)` takes new points and marks only the segments that moved; their lengths are measured when a read asks, and nothing allocates once the curve exists |
| `src/services/` | Long-lived services (`effects`, `pool`, `mover`, `texture_loader`, `enabled_effects`, `frame_store`) |
| `src/services/enabled_effects.luau` | The ConstantVFX tag's passive loops and every EmitDuration window. `enabled_effects.add(obj)` starts an instance's passive loop once (the tag listener, `enabled_effects.switch`) and `enabled_effects.remove(obj)` ends it; the loop ticks while Enabled is true and the instance sits where it may emit. `enabled_effects.placed(obj)` answers where it may emit and `enabled_effects.moved(obj, callback, destroyed)` connects the two signals that follow it, `callback` on every move and `destroyed` once it is destroyed, and returns a scope holding both connections; these two are the seams a spec stands in. The tag means "this effect loops by itself". `enabled_effects.switch(obj, enabled)` is the one path that turns an instance's Enabled on or off: `api.enable`, `api.disable` and a plain emit of an enabled lightning, bezier or mesh all go through it. It stores Enabled, fires the listener itself on a cached instance, and for a constant module starts the loop (tagging the instance in Studio's edit mode) or stops it, in edit mode also removing the tag and the loop record, and in a running game keeping a tagged instance's tag and record while an untagged instance's record goes; never write Enabled with `attr.set` alone. `enabled_effects.window(ctx, module, duration, speed)` is the whole of an EmitDuration emit of a constant module: an emit of its own under the effect's (`lifetime.emit(scope.emit, scope.clock)`, `constant = false`), its Speed row on its clock (`lifetime.speed(scope, speed, window.clock)`), a tick dispatched with `constant` true as it opens and every `1 / Rate` of its clock after, sealed and awaited once `duration` of the effect's clock has run; a window ignores the tag, and two windows of one instance never share anything. When the window's Speed comes to rest at 0 its clock halts and every tick still playing is marked halted |
| `src/services/frame_store.luau` | The authored frame sets of a mesh effect. A model's `FrameSet` attribute names a set; its `Frames` folder (also carrying `FrameSet`, tagged `__forge_excludeFromEmit`, optional `UnionSize` and `UnionCenter`, and an optional whole `FrameCount`) holds frames named `"1"` to `"N"` (frame k is the BasePart named k; a non-BasePart child never shifts the numbering), each a MeshPart (optional SurfaceAppearance child) or a Part with a SpecialMesh (optional Decal child), with optional `FrameSize` and `FrameCenter`. `frame_store.init(scope)` makes the park holder and must run before `texture_loader.init`, which warms tagged instances in its own init; `find(model, key)` answers the set for a key, registered once from the first folder that names it, and in a running game on the client detaches the folder from the model. A folder holding fewer frame parts than its `FrameCount`, or a gap in its numbering (no part named k below the highest), with or without a `FrameCount` (still streaming in, or an apply not done with it), is neither registered nor detached, so a later `find` reads it whole; a detached folder is kept by key through a restart of the store (`init` does not forget it, and a later whole folder under the key replaces the kept one; `init` puts the budget back to its default), and `find` falls back to it when the model holds none. `warm(set, wearer?, textures?)` parks every frame out of view (anchored, no collision, query or touch, size zero, at `CFrame.new(0, -20000, 0)`) so the engine loads its meshes and maps: a material's home and a mesh copy worn under a surface at Transparency 0.999, which still loads its maps, and a bare mesh copy at 1. `wearer` is the part the pieces copy (a mesh's template, a legacy mesh's `Start`) and `textures` the texture set the same model plays; a MeshPart frame's mesh copy wears a copy of the wearer's SurfaceAppearance, else of the texture set's first material, read as the set is built and built again when the wearer gains or loses one, and a Part frame's copy (a SpecialMesh) never wears one. It lets sets go once the parked texture count passes the budget, only when this warm built or parked something (a warm of a set already parked evicts nothing). It asks `containers.of("frames")` every time, and when the holder is not the one the copies were built under (it was destroyed), every set's copies are dropped and built again under the new one. A build is whole or nothing: a frame or material that is not Archivable clones to nil, so what the build made is destroyed, the set stays unbuilt, one warning is logged and the set is not built again until a frame or material it was refused for changes. `lend(set, index)` hands a frame's material out and `giveBack(set, index, material)` takes it back (raising when nothing is lent), restoring its authored glow and, for a Decal, its authored `Transparency`; eviction takes the least recently warmed sets first and skips a set with a lent frame, one holding no textures and the one being warmed, so the budget may be exceeded while one needs it. `setBudget(textures)` and `getBudget()` count textures (one map of one frame), 128 by default, `setBudget` letting sets go at once, `api.setFrameBudget` and `api.getFrameBudget` being the public pair. `findTextures(model, key)` answers a texture set the same way (register, detach, the template's folder detached too, the shared sets, budget and eviction): a model's `TextureSet` attribute names it, its `Textures` folder carries `TextureSet` and `TextureCount` (the whole count, read as `FrameCount` is), and a `TextureFps` of its own only as a record, since the runtime plays at the model's `TextureFps` knob alone, and holds carriers named `"1"` to `"N"`, each a zero-size invisible part holding one SurfaceAppearance; its frames carry only a material (no mesh is parked for them, no bounds, no union). No module writes a property a game script cannot write (no SurfaceAppearance map, Decal emissive mask or `MeshPart.MeshId`); `frame_store.engine` is the seam a spec stands in |
| `src/mod/frame_show.luau` | One mesh piece playing a frame set. `frame_show.new(set, piece, start, opts?)` answers a show with `show(index, size)` (answers the size to draw at; switches the piece's mesh through `ApplyMesh` or the SpecialMesh `MeshId` only when the set's frames do not all share one mesh (`set.meshes`), and swaps in the lent frame's material only when some frame has one (`set.materials`) and `opts.materials` is not false, which a mesh wearing a texture set passes, so the piece keeps the texture set's surface; showing the index already shown changes nothing; a frame whose mesh the store's preload has not settled holds the frame last shown, or the start before any, unless the piece already wears that mesh, as a start wears its first frame's, when it shows at its own bounds with no apply), `glow(strength, tint)` (scales a frame material's own `EmissiveStrength` and `EmissiveTint`, the lab's baked glow, by the effect's), `fade(transparency)` (a Decal frame's `Transparency` is `1 - (1 - authored) * (1 - transparency)`, the mesh's `FrameTransparency` row, kept across frame switches; a SurfaceAppearance is never faded) and `release()` (a no-op before any show and after a release; a frame with no material gives the piece its own appearances back for that frame). On a SpecialMesh piece a frame's offset is the authored Start offset plus the frame's center off the union's times `Scale`; on any other piece the fitted size is written only when it changed. `release` gives the lent material back and restores start's mesh (a SpecialMesh's `MeshId` as `new` read it) only after a switch, so a piece that never changed mesh is left alone. `frame_show.engine` is the seam a spec stands in |
| `src/effects/particle.luau`, `src/effects/particle_2d.luau` | The 3D and the 2D emitter share their rows (`particle.rows()`, made anew for each module, since registering freezes a row) and their emit (`particle.play(ctx, attrs, props, place)`, `place` answering the instance it plays on or nil). A 3D emitter outside the workspace plays on a clone of its ancestry; a `ParticleEmitter2D` (a gui emitter, its Size, Speed and Acceleration in offset pixels, its texture a Content in `TextureContent`) plays where it is, only under a GuiObject and only in the editor or on a client, and emits nothing anywhere else; it declares `copies` and hands itself to `ctx.copied` only once it plays, so the dispatcher never drives its rows' modifiers where it cannot draw (on a server they would write every frame and replicate). retime and resize scale its engine rows as the 3D one's, its pixels as studs; its EmissionOffset and EmissionSpread are fractions of its parent and stay as they are |
| `src/effects/trail.luau`, `src/mod/common/flipbook_rows.luau` | A trail plays in place, never on a copy. `EmitDelay`, then `EmitDuration`: 0, the default, switches it on and leaves it on, which is what every emit did before trails had a window, so a trail saved then (a nested one its parent's emit switches on included) plays as it did and the emit ends at once; above 0 a window holds it on through an `Enabled` writer (two emits' windows overlap, the last to close lets it go, a clear switches it back) and the effect waits out the trail's `Lifetime` after it, so its duration is the window plus the Lifetime; below 0 the emit never touches `Enabled`, which is how a nested trail opts out of its parent's emit. ## Setup

```sh
rokit install --no-trust-check
```

`--no-trust-check` is required because `UpliftGames/wally` is untrusted by default and plain `rokit install` aborts on it. This is the same invocation the plugin repo's release workflow uses.

If `stylua` reports `No such file or directory`, you skipped this step: `rokit.toml` pins StyLua 2.4.0 while the parent plugin repo pins 2.5.2, so the shim will not resolve until the pinned build is fetched. Never work around it by calling a binary out of `~/.rokit/tool-storage/`; that silently formats with the wrong version.

`selene.toml` sets `std = "roblox+luau"`, which needs a generated `roblox.yml`. It is 730 KB of generated API surface, so it is gitignored rather than committed:

```sh
selene generate-roblox-std
```

Run that once after cloning. Without it `selene` cannot resolve the standard library. CI does not need it, because selene is not a gate there yet.

## Tests

`lune run tests/run` is the suite CI judges every push and pull request by, and every spec in it is deterministic. The timing and allocation gates (`*_cost.spec.luau`, under `lune run tests/cost`) measure the process they run in, so they live in that second lane, run by hand when a change is about speed, and never gate a pull request. A new gate that compares a cost or counts allocations goes in a `_cost` spec, not in `tests/run`.

## Always run stylua

```sh
stylua --config-path ./stylua.toml src/
```

Required before every commit. stylua is necessary but not sufficient: it will not sort your requires, remove a header comment, or fix a bare `error()`.

Build with `rojo-build-noalias -o output.rbxm`. The TypeScript surface (`index.d.ts`) is separate: `bun run typecheck`, `bun run lint`.

## Style summary

- **2-space indent.** Enforced by stylua.
- **No `--!strict`.** Most files carry no mode comment at all. `--!native` / `--!optimize 2` only for genuinely hot numeric code.
- **No header comments.** Never open a file with a prose block explaining it.
- **Comment rarely**, only where the code cannot say it itself. Lowercase fragment, no trailing period, labelling the lines beneath. Many files here have zero comments and that is correct.
- **Blank line after every closing `end`.** Separate logical blocks.
- **Annotate every parameter. Leave return types inferred** unless the return is optional, a tuple, or a named type.
- **Guards are three lines.** No one-line `if x then return end`, ever.
- **Nothing on the pass thread yields.** Step bodies, a tween's `fn` and `done`, and any cleanup or `lifetime.defer` callback reached from them run on the scheduler's pass thread; a yield there leaves the pass open and every frame is skipped until it resumes. Put blocking work in `task.spawn`. `tween.wait`, `lifetime.wait`, `lifetime.await` and `lifetime.awaitJoin` refuse to run there (`scheduler.inPass()`).
- **Errors go through `@mod/logger`**, not bare `error()`. Per-frame hot paths absorb bad input silently instead.
- **Sort interchangeable siblings by identifier length, ascending, within each blank-line group.** Governs requires and flat lists. It does not override semantic order: `scaleStart` still precedes `scaleEnd`.
- **Naming:** `snake_case` files and object internals, `camelCase` locals and functions and config fields, `PascalCase` class modules and exported types and public API fields, `UPPER_CASE` constants.
- **No em or en dashes anywhere**, in code, comments, or docs. This includes ` -- ` used as a prose dash. Rewrite with a comma or a second sentence.
- **US spelling everywhere**: code, comments, docs, commit messages and text an artist reads (`color`, `behavior`, `honor`, `neighbor`, `meters`). `cancelled` and `labelled` stay, as US spellings too and the ones the API already uses (`fx.cancelled`).
- **A registered effect module declares every value it needs as a row and reads it through `emit(ctx, attrs, props)`; it never calls `attr.get` on its own instance.** Every effect is registered; there is no unconverted effect. The one `mods.track` left reads a knob authored on a decal the dispatcher reaches separately, and no effect ever reads a `_Start`, `_End` or `_Curve` attribute; the old format is `legacy_mods`' business. A module that the ConstantVFX tick may emit declares `constant = true` and reads `ctx.constant`; when `EmitDuration > 0` and `ctx.constant` is not set it calls `enabled_effects.window(ctx, module, attrs.EmitDuration, attrs.Speed)` after its EmitDelay and returns. `ctx.shared` carries the per-emit maps. A module never reads a `_Start`/`_Duration`/`_Curve` quad to play a ramp: the ramp is a default modifier on the row it changes, and a legacy-only input behind it is a hidden row.
- **A v2.4.0 parity fix ports what v2 meant, never its code as written.** A name can mean something else in v3: the ConstantVFX tag was a switch of its own in v2, and since 2026-10-03 it follows Enabled and is removed whenever an instance is switched off in edit mode, so v2's `HasTag(ConstantVFX)` check copied onto the mesh's EmitDuration made every disabled mesh emit once. Before porting a v2 condition, check what each tag, attribute and default in it means in v3 today. A spec for such a fix reaches its fixture's state through the runtime's own calls (`enabled_effects.switch`, `effects.emit`), never by setting tags and attributes into a combination v3 cannot reach: the spec that shipped with that check built a tagged and disabled model, which edit mode never holds, and passed.
- **Effects never call `task.wait`, `task.delay` or `os.clock`, and never connect to or bind a RunService frame signal.** Wait with `lifetime.wait(scope, seconds)`; step with `tween` or `lifetime.step(scope, fn, phase)`. A step that reads where a parent is follows (`lifetime.step(scope, fn, "follow")`, or a tween's `follow` argument set to `scope.depth`); a screen places itself in `"screen"`; everything else computes.
- **A module never multiplies a delta by a speed.** Every step, tween and `lifetime.wait` already advances on the effect's clock. An authored Speed row is `lifetime.speed(scope, row)` right after `EmitDelay` (a module the ConstantVFX tick may emit calls `utility.speedFrom(scope, ctx.constant, row)` there instead: a passive tick takes its own Speed row, a window's tick takes none, since a window's Speed is on the window's clock, which its ticks hang from), and a tween ends by itself once that speed rests at 0 for good (`scope.clock.halted`), where a `lifetime.step` that should end then checks `timeline.halted` itself. A piece the engine times (a particle emitter, a beam's texture, a sound, debris) goes through `@mod/adapters`. A controller's `Scope` and `TimeScale` reach a module only through its clock; a module never reads them.
- **Effects never build a Promise or read `Finished`.** A body waits for its pieces and child emits through `lifetime.join`: count a piece in with `lifetime.add` (or run it with `lifetime.spawn` when it yields), hand the join to `scope.effects.emitNested`/`emitFromFolder`/`emitOnFinish`, and end with `lifetime.awaitJoin`. Name the local for what it counts (`outstanding`, `children`, `clones`), never `pieces`: `piece` is lane machinery. `pkg/Promise` is required only by `src/services/effects.luau`, which builds the public `Finished` when somebody reads it, and `src/types.luau`, which types it.
- **Row ids carry no underscores; old spellings are aliases.** A value that is a Roblox property is a property row. The vocabulary is fixed: module fields `id display classifier components attributes properties layout duration constant emit selected events template`; ctx fields `ref obj scope effect duration shared constant piece`; never name a new public thing `select`, `claims`, `rest`, `ramp`, `each`, `ownStart`, `span`, `stamp`, `drive`, `track`, `rand`, `hold` or `arbiter`. `sdk.hold` is `lifetime.hold` behind the facade and `sdk.speed`'s `track` a row's Track view, the same things those words already name. The facade's names are `knob`, `mod`, `wait`, `step`, `curve`, `tween`, `hold`, `join`, `spawn`, `await`, `emit`, `getWriter`, `getAttributeWriter`, `speed`, `apply`, `refresh`, `looping`, `warn`, `lock`, `context`, `guiRoot`, `lerp`, `color`, `shape` and `bezier`, a custom effect's fields are `sdk_version`, `id`, `display`, `classifier`, `components`, `layout`, `constant`, `params`, `duration`, `emit`, `unload` and `template`, and the tag is `VFXForgeEffect`. `priority` names an emit's rank in the writer list (the `{ priority = n }` emit option, the emit record field and the handle's `SetPriority`) and nothing else. `walk` is not reserved. `lane`, `lanes`, `piece`, `fire`, `fired`, `runs`, `runFor`, `events`, `draw`, `has`, `reach`, `still`, `own` and `since` name the lane machinery in `src/mod/mods.luau` and nothing else; read one as that machinery wherever it appears, and never give one to anything outside it. `PROPERTY_UNITS` and `RATIOS` are the two tables `retime` and `resize` keep for engine properties and ratios. The clock's names are `clock`, `factor`, `speed`, `paused`, `scale`, `unscale`, `halted`, `uniform`, `watch` and `refresh`; a local that holds an effect's clock is `timeline`. `lifetime.speed`'s optional third parameter is `scaled`, the clock the row drives in place of the effect's own. The ConstantVFX service's public names are `enabled_effects.add`, `remove`, `switch`, `placed`, `moved`, `token`, `window` and `ticking`; a passive loop is the tag's, a window is an EmitDuration emit's, and neither word names anything else. `clock.scale` is a controller's multiplier on a clock. A Track view's methods are `at` and `redraw` (the same row with its draws made again, for one piece of an emit). A tween's callbacks are `fn` and `done`; a Curve's fields are `duration`, `shape` and `fn`, and its one method is `at`; `tween.play` and `tween.wait` take one as `eased`.

Where this package and the [Roblox Lua style guide](https://roblox.github.io/lua-style-guide/) disagree, this package wins. The guide is a gap-filler only.

## Files that are not examples

Two files have drifted and are **not** precedent. Do not copy their conventions, however recent they are. Recency is not authority:

- `src/mod/common/path.luau`
- `src/mod/modifiers.luau`

Two more are vendored MIT code by Daniel P H Fox and were never house style:

- `src/mod/color/Oklab.luau`
- `src/mod/color/sRGB.luau`

Those two vendored files are the only ones left carrying `--!strict`, and only because editing vendored code to match house style would fork it from upstream for nothing. Everything else in `src/` and `tests/` has no mode comment at all.

**Everything under `pkg/` is third-party** (`Z`, `tiniest`, `Promise.luau`, `Shake.luau`, `GoodSignal.luau`), some vendored and some a submodule. It is not house style, it is not precedent, and it is not yours to reformat. Never run stylua over `pkg/`, never cite it, and keep local changes out of it so upstream updates stay clean.

**Imitate these instead:** `src/mod/recolor.luau`, `src/effects/shockwave_ring.luau`, `src/types.luau`.
